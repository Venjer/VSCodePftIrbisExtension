# Change Log

All notable changes to the "pft" extension will be documented in this file.

Check [Keep a Changelog](http://keepachangelog.com/) for recommendations on how to structure this file.

## [0.1.2] - 2026-07-27

### Fixed
- `&` больше не обязателен перед `s`/`val`/`f`/`rsum`/`rmax`/`rmin`/`ravr`/`l`/`ref` для hover
  и подсветки синтаксиса. Проверка на корпусе реальных боевых форматов ИРБИС показала, что эти
  функции почти всегда вызываются без `&` (голый идентификатор, за которым сразу следует `(`,
  интерпретируется как вызов функции независимо от `&`); `&unifor(`/`&uf(` в реальных форматах
  всегда пишутся с `&` — там поведение не менялось.
- Статичные сниппеты (`snippets/irbis.json`) для `s`/`val`/`f`/`rsum`/`rmax`/`rmin`/`ravr`/`l`/`ref`
  вставляли `&` — теперь, как и динамическое автодополнение, вставляют вызов без `&`.

### Added
- Hover-подсказки для ключевых слов `if`/`then`/`else`/`fi`/`and`/`or`/`not`/`break` — у
  `break` отдельно описано неочевидное поведение внутри группы без `if`.
- Hover-подсказки для операторов сравнения `= <> < > <= >= :` — у `:` («содержит») описан особый
  случай пустой правой части.
- Hover-подсказки для префиксов ссылок на поля `v`/`d`/`n`/`g` с разбором частей `^подполе`,
  `*смещение`, `.длина`, если они присутствуют в конкретной ссылке. Отдельно подчёркнуто, что
  `d`/`n` сами по себе никогда не выводят текст — это только признак присутствия/отсутствия.
- `.gbl` (файлы языка глобальной корректировки ИРБИС) добавлен в language id `irbis-data` —
  только распознавание и кодировка Windows-1251, как у остальных служебных форматов.

## [0.1.1] - 2026-07-27

### Added
- Кодировка Windows-1251 по умолчанию для `.pft` через `contributes.configurationDefaults`.
- Новый лёгкий language id `irbis-data` для служебных форматов ИРБИС (`.fst`, `.mnu`, `.par`,
  `.wss`, `.stw`, `.ws`) — только распознавание и кодировка Windows-1251, без грамматики.
- Подсветка повторяющихся литералов `|...|` и `|...|+` в TextMate-грамматике.
- ESLint (flat config, `typescript-eslint`) и `.editorconfig`.
- Переход по F12/Ctrl+клик расширен помимо `@name`: `&uf('K<справочник>\')`/`&uf('K<справочник>!')`
  → `<справочник>.mnu`, `&uf('6<формат>')` → `<формат>.pft`.
- Hover-подсказки для проверок присутствия `p()` (истина, если поле/подполе присутствует) и
  `a()` (истина, если отсутствует) — раньше не были задокументированы вовсе.

### Fixed
- Форматирование документа (Ctrl+Shift+I) сохраняет исходный перевод строк (CRLF/LF) вместо
  того, чтобы всегда приводить его к LF.
- Диагностика пересчитывается с задержкой 300 мс после изменения документа вместо полной
  ретокенизации на каждое нажатие клавиши.
- Висячая запятая в `language-configuration.json`, из-за которой файл не был валидным строгим JSON.
- Грамматика подсветки: строковые литералы больше не считают `\` символом экранирования — в PFT
  его нет (кавычка всегда закрывает литерал сразу же, как и в токенизаторе). Раньше это ложно
  "проглатывало" закрывающую кавычку в конструкциях вида `&uf('Klang.mnu\', ...)` и обрывало
  подсветку до следующей случайно попавшейся кавычки в файле. Заодно строковые литералы больше
  не переходят на следующую строку, если не закрылись — как и в токенизаторе.

### Changed
- `example.pft` перекодирован из UTF-8 в Windows-1251 (CRLF и отсутствие BOM сохранены);
  `.gitattributes` фиксирует `working-tree-encoding=windows-1251` для `*.pft`.

### Removed
- Справочник полей RUSMARC и связанные hover/автодополнение (`marcFields.ts`) — покрывал лишь
  11 полей из сотен возможных, что создавало ложное впечатление полноты. Подсказки по функциям
  UNIFOR и встроенным функциям не затронуты.

## [0.1.0] - 2026-07-27

### Added
- Встроенные функции верхнего уровня `&s`, `&val`, `&f`, `&rsum`, `&rmax`, `&rmin`, `&ravr`, `&l`, `&ref`: автодополнение, hover, сниппеты и подсветка.
- Hover-подсказки по полям и подполям RUSMARC на основе встроенного справочника.
- Переход к подключаемому формату: `@name` → `name.pft` в рабочей области.
- Диагностика: парность `if`/`fi`, парность скобок, незакрытые строковые литералы.
- Подсветка проверок наличия `p()`/`a()` и подключаемых форматов `@name`.
- Горячая клавиша Ctrl+Shift+I для форматирования документа.
- Модульные тесты токенизатора, форматтера, анализатора, справочников UNIFOR/builtins/полей и
  сценариев автодополнения и hover (`npm test`, 63 теста).
- Тест-ограничитель, не допускающий импорт `vscode` в доменном и прикладном слоях.

### Changed
- Библиотека UNIFOR расширена примерно до 80 функций.
- Форматирование переписано на основе токенизатора: отступы расставляются по вложенности
  `if`/`fi` и групп в скобках, содержимое литералов и комментариев не изменяется.
- Автодополнение и hover используют единый источник данных вместо двух пересекающихся списков.
- Исходный код реорганизован по слоям: `domain` (язык, форматирование, диагностика, справочники),
  `application` (сценарии автодополнения, hover, перехода по `@include`, выбора функции),
  `infrastructure/vscode` (адаптеры к API редактора). Доменный и прикладной слои не зависят
  от `vscode` и покрываются обычными mocha-тестами без запуска редактора.
- Сборка выводится в `out/`; скомпилированные файлы больше не лежат рядом с исходниками и не
  отслеживаются Git.
- Значок расширения заменён с анимированного GIF 60×41 на PNG 512×512 (требование Marketplace).
- Расширены метаданные `package.json` для публикации: `license`, `keywords`, `bugs`, `homepage`,
  дополнительные `categories` (Formatters, Linters, Snippets), `galleryBanner`.

### Fixed
- Обработка комментариев: `/*` действует до конца физической строки. Правило блочного
  комментария `/* ... */` удалено — такой конструкции в PFT нет.
- Коды даты и времени: компонент задаётся кодом после `3` (`300` — год, `301` — месяц,
  `302` — день, `31` — время). Прежние `30`/`32`/`39` описывали несуществующее поведение.
- Описание счётчика `S`: формат `S[<шаг>][<буква>]`, а не набор одиночных кодов.
- Из грамматики и сниппетов удалены `case`, `select`, `while`, `do`, `for`, `continue`,
  `return` — этих конструкций в языке нет.

### Removed
- Неиспользуемая зависимость `socks`.
- Собранный артефакт `pft-0.0.3.vsix` из-под контроля версий (`*.vsix` добавлен в `.gitignore`).
- Устаревший дублирующий список функций и нерабочая схема `irbis-help://` в провайдере определений.
- Скаффолдинг `vsc-extension-quickstart.md`, описывавший неиспользуемую тестовую схему.
- Неиспользуемая функция `searchFields` в справочнике полей.

### Packaging
- `.vscodeignore` больше не пропускает исходники TypeScript, тесты, `tsconfig.json`,
  `package-lock.json` и служебные файлы в `.vsix` — пакет содержит только собранный `out/`,
  грамматику, сниппеты и метаданные.
- Добавлен `@vscode/vsce` в devDependencies и скрипт `npm run package`.

### Примечание об источнике данных
Описания функций UNIFOR и модель синтаксиса PFT сверены с независимой реализацией
интерпретатора PFT в проекте Fribis (MIT, тот же автор), проверенной дифференциальным
тестированием против `IRBIS64.dll`. Справочник полей RUSMARC — собственные данные
расширения, пополняется вручную.
